## TRIAXIS run over its own history

### H0 — Original persona architecture

**Historical state:** SELF/REALITY → DEVIL → ANGEL → SYNTHESIS.

**Audit:** `REVISE` as a default core.

Reason:

- later direct tests found no incremental Trialectic value on Tool Trust Routing and Valid-but-Divergent Tools;
- InterveneBench produced real countermodel rescues but also harms and null-net batches;
- same-model debate has not earned default invocation;
- the current system correctly demoted DEVIL to one conditional action-changing countermodel and removed mandatory ANGEL/SYNTHESIZER/persona theatre.

**Retained residue:** the original useful intuition survives only as bounded adversarial search when a concrete unresolved assumption can change the action and no direct discriminator already settles it.

### H1 — v2.3-v2.10 boundary-hardening line

**Audit:** `PASS WITH CONDITIONS`.

Observed native failure pressure repeatedly selected:

```text

→ CONTEXT SCOPE
→ PROVENANCE
→ STATE / DEPENDENCY BINDING
→ VERIFICATION
```

Representative frozen surfaces included malformed input, semantic ingress, action routing, role/scope contamination, graph serialization, correlated evidence and release integrity.

This is strong evidence that the historical mutation pressure was not principally “more debate.”

Condition: the historical failure-surface percentages are from different surfaces and must not be pooled into one accuracy leaderboard or treated as external cognitive-lift evidence.

### H2 — v2.34-v3.32 runtime / assurance expansion

**Audit:** `REVISE` as cognitive core and primary product direction; `HOLD AS ORTHOGONAL ENGINEERING` where native runtime evidence supports it.

The expansion added identity, delegation, authorization, credentials, policy, rollback, runtime assurance, provider idempotency and release-integrity machinery.

The later project correction — “the big TRIAXIS stack was a wrong product direction” — is supported by both internal scope analysis and external landscape research. Mature external standards and platforms already cover much of this surface. This machinery may still be useful as adapters or separate engineering, but it is not evidence that TRIAXIS is a superior reasoning architecture.

## Audit of the research process itself

### What TRIAXIS did well

1. It repeatedly invalidated or narrowed its own metrics and claims when evidence failed.
2. It preserved a known Git gap instead of fabricating continuity.
3. It introduced preregistration, source binding, scoring freeze, post-freeze audit and quarantine.
4. It honored at least one explicit cost survival failure (v0.11) rather than counting accuracy alone.
5. It stopped same-mechanism cycles when fresh effect was absent (v0.12).
6. It keeps the broad claim `UNSUPPORTED` despite positive mechanism-level results.

### Remaining process risks

1. **Metric fork risk:** project integrity metrics can legitimately detect evidence defects, but they can also reverse the apparent direction of a benchmark result. Native/raw metrics must remain primary and separately visible.
2. **Selection enrichment risk:** trigger-enriched or top-difficulty task selection is useful for mechanism stress testing, but cannot support prevalence or broad-population claims.
3. **Reconstructed-baseline risk:** reproduced behavior is not byte-identical provenance.
4. **Same-model contamination:** many self-runs and some comparative arms are not independent evaluators.
5. **Benchmark concentration:** recent evidence overweights exact programming/tool tasks relative to judgment-heavy domains.
6. **Missing historical causal discriminator:** the external weak-model evolution replay has not been run.
7. **Sunk-cost relapse risk:** the large runtime stack remains available in history and can be accidentally re-imported into the cognitive core without new evidence.

## Terminal decision

`PASS WITH CONDITIONS` for the **current research direction**, not for broad TRIAXIS efficacy.

The history does not justify reviving the full Trialectic persona stack or the v3.32 runtime stack as the core. It does justify continuing a much smaller research object:

> **an evidence-bound controller that binds state, acquires only decision-relevant evidence, validates the instrument and semantic applicability, commits only on a complete evidence chain, and stops/reopens explicitly.**

The project should now prefer **falsification of this minimal core** over adding new architecture.
